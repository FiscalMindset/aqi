### Why "anchored on persistence"

The first version regressed to the mean and **lost** to the persistence
baseline. Fitting the residual against the nearest station's last hour makes
persistence the null hypothesis: a model that learns nothing predicts a delta
of 0 and exactly reproduces the baseline. To beat it, it must find real signal.
The served prediction is `station_lag1 + model(features)`, with the correction
clipped at the p95 of `|actual - anchor|` seen in training (46 ug/m3) so an out-of-distribution feature vector cannot emit a correction larger than the value it is correcting.

## Features (27)

Calendar (hour, weekday, month, sin/cos), weather at t from Open-Meteo (wind
speed/direction/gusts, temperature, humidity, precipitation), static geography
from OpenStreetMap (distance and count within 5 km of landfills, industry,
construction, signalised junctions), and the nearest station's own history at
strictly earlier hours (lag-1h, lag-24h, rolling 6h).

The target station's current reading is never an input; a leakage test proves
it. Every estimate served by the API carries a per-parameter contribution in
ug/m3, computed by occlusion with the persistence anchor held fixed.

## Honest limits

- The interval is conformal, not learned: the raw p10/p90 models under-cover
  during rapid swings, so the API serves the conformal band.
- CPCB categories are defined on 24-hour averages and are applied here to
  hourly values, which is deliberately conservative.
- The model corrects an official reading; it does not replace one. Official CPCB
  station data remains authoritative.
